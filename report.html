Abstract

In modern marketing analytics and customer relationship management (CRM), planning multi-product promotional campaigns requires measuring the distinct reach of an audience. When marketers aggregate customer lists across multiple products, customers who purchased multiple promoted items are counted multiple times. This naive summation grossly overestimates unique audience size, causing distorted return-on-ad-spend (ROAS) projections and excessive advertising spend.

RetailReach addresses this fundamental challenge by applying the Principle of Inclusion–Exclusion (PIE), Discrete Graph Theory, and Deep Learning to 541,909 real-world e-commerce transactions from the UCI Machine Learning Repository Online Retail dataset. The system calculates exact audience unions by evaluating all 2n − 1 combinatorial intersections for up to five concurrent product sets, tracking alternating Bonferroni bounds, rendering dynamic 3D volumetric Venn manifolds via WebGL/Three.js, modeling product co-purchase graphs with Kruskal's Maximum Spanning Tree, and training an in-browser Multi-Layer Perceptron (MLP) neural network to predict multi-audience overlap in O(1) time.

On a representative three-product benchmark (Regency Cakestand, White Heart T-Light Holder, Party Bunting), a naive sum of 2,445 customer entries collapses to an exact unique reach of 1,772 customers, safely removing 673 redundant records (a 27.53% overlap distortion). An independent computational check between the combinatorial formula and direct set unions confirmed 100% exact numerical agreement across all tested combinations.

1. Problem Identification and Industrial Relevance

1.1 The Audience Inflation Dilemma

Consider a marketing campaign promoting n products: P1, P2, …, Pn. For each product Pi, historical sales records identify a set of distinct customer buyers, denoted Ai, with cardinality |Ai|. When campaign managers launch cross-promotions, they frequently compute projected audience size as the naive sum of individual list sizes:

Reachnaive = ∑i=1n |Ai|

This uncorrected sum assumes that customer sets Ai and Aj are mutually disjoint (Ai ∩ Aj = ∅ for all i ≠ j). In retail environments with strong cross-category affinity, this assumption fails catastrophically. Multi-product buyers belong to multiple target sets simultaneously, resulting in significant overcounting:

  • Budget Waste: Marketing teams over-allocate ad spend based on inflated impression estimates.
  • Ad Fatigue: High-value customers who purchased several promoted products receive repetitive, uncoordinated advertisements.
  • Distorted Metrics: Conversion rates computed against an inflated denominator appear artificially low.

1.2 The Combinatorial Challenge

Calculating exact union size |A1 ∪ A2 ∪ … ∪ An| requires evaluating all 2n − 1 non-empty subsets. For large numbers of products, exact enumeration becomes computationally prohibitive (Ο(2n)). This creates a pressing need for:

  1. Strict analytical bounds (Bonferroni Inequalities) to establish guarantees at early stopping orders.
  2. Graph-theoretic topological modeling to uncover high-affinity product communities.
  3. Deep learning surrogates capable of predicting overlap ratios in constant time (Ο(1)).

3. Mathematical Foundations: Set Theory & Bonferroni Bounds

3.1 The Principle of Inclusion–Exclusion

Let A1, A2, …, An be finite sets. The cardinality of their union is defined by the alternating sum:

|∪i=1n Ai| = ∑k=1n (−1)k−1 Sk

where Sk represents the sum of cardinalities of all k-tuple intersections:

Sk = ∑1 ≤ i1 < … < ik ≤ n |Ai1 ∩ Ai2 ∩ … ∩ Aik|

3.2 Rigorous Proof via Characteristic Indicator Functions

For each customer element x ∈ U, let 1Ai(x) be the indicator function:

1Ai(x) = 1 if x ∈ Ai, else 0

An element belongs to the union if and only if it does not belong to the complement intersection:

1∪ Ai(x) = 1 − ∏i=1n (1 − 1Ai(x))

Expanding this algebraic product yields:

1∪ Ai(x) = ∑i 1Ai(x) − ∑i < j 1Ai ∩ Aj(x) + … + (−1)n−1 1∩ Ai(x)

Summing both sides over all elements x ∈ U confirms the theorem unconditionally: ∑x 1S(x) = |S|.

4.3 Kruskal's Maximum Spanning Tree (MST)

To identify the core structural backbone connecting all products without redundant cycles, RetailReach adapts Kruskal's algorithm to compute the Maximum Spanning Tree:

  1. Sort all 276 candidate edges in non-increasing order of weight: w(e1) ≥ w(e2) ≥ … ≥ w(em).
  2. Initialize a Disjoint Set Union (DSU) data structure with path compression and union-by-rank.
  3. Iterate through sorted edges; add edge (u, v) to tree T if Find(u) ≠ Find(v), then Union(u, v).
  4. Terminate when |T| = |V| − 1 = 23 edges.

5. Deep Learning & Machine Learning Overlap Predictor

5.1 Multi-Layer Perceptron (MLP) Architecture

While Inclusion–Exclusion scales exponentially (Ο(2n)), real-time bidding engines require audience predictions in constant time (Ο(1)). RetailReach implements a custom feedforward neural network trained directly in-browser using stochastic gradient descent:

[Input: 4 Features] → [Dense: 8 Neurons, ReLU] → [Dense: 6 Neurons, ReLU] → [Output: 1 Neuron, Sigmoid] Features: [ Σ|A_i|/3500 , max|A_i|/1000 , Mean Pairwise Jaccard , n/5 ] → Predicted Overlap Ratio ∈ [0, 1]

5.2 Mathematical Formulation of Backpropagation

Let x be the 4-dimensional input feature vector. The network forward pass computes:

h1 = ReLU(W1 x + b1)  |  h2 = ReLU(W2 h1 + b2)  |  ŷ = σ(W3 h2 + b3)

Given ground-truth overlap ratio y and Mean Squared Error loss L = (ŷ − y)2, backpropagation updates all weight layers via chain rule:

∂L/∂z3 = 2(ŷ − y) ŷ (1 − ŷ)  →  ∂L/∂W3 = (∂L/∂z3) h2T

The gradients propagate through both hidden layers down to the input layer (W1, b1), enabling genuine representation learning across 120 epochs of live in-browser gradient descent.

7.2 Data Cleansing and Transformation Pipeline

Raw retail transaction logs contain significant operational noise. The preprocessing pipeline systematically cleans records:

  1. Cancellation Removal: Invoices prefixed with 'C' indicate canceled or refunded transactions and are purged.
  2. Anonymous Session Filtering: 135,080 transactions lacking a valid numeric CustomerID are excluded to prevent false set collisions.
  3. Quantity and Price Validation: Nonpositive unit prices and zero/negative quantities representing stock adjustments are discarded.

10. Conclusion and Future Research Directions

RetailReach demonstrates the direct real-world application of Discrete Mathematics and Graph Theory to enterprise data problems. By pairing the mathematical rigor of the Principle of Inclusion–Exclusion with Three.js 3D spatial visualization, Kruskal's graph algorithms, and in-browser Deep Learning, the project bridges theoretical mathematics and modern software engineering.

Future extensions include generalizing pairwise graphs to hypergraphs that represent entire shopping baskets directly, using streaming cardinality estimators like HyperLogLog for real-time scale, and building integer linear programming solvers to optimize campaign ad spend under budget constraints.
